# 불량 대화 파일 기반 규칙 분석 결과

분석일: 2026-09-14. 사용자 제공 `불량.txt` 전체를 로컬에서 분석했다. 모델 가중치 재훈련, 외부 AI 업로드, 승인 요청 전송, ERP 등록은 수행하지 않았다. 학습 결과는 재사용 가능한 추출 코드·후보 어휘·검토 목록·회귀 테스트로 보존한다.

## 범위와 수치

| 분류 | 메시지 수 |
|---|---:|
| 전체 | 5,042 |
| 지정 작성자 외 | 835 |
| 지정 작성자의 사진·동영상·파일 단독 | 2,572 |

| 매칭 단계에 넘길 구조화 후보 | 877 |

지정 작성자 총 4,207개. `김원영차장`을 김원영으로 명시적으로 연결하며 비슷한 다른 이름은 허용하지 않는다. 구조화 후보 877개에는 품목 952개가 포함된다. 모든 추출 결과의 승인 값은 false다. 후보는 실제 마스터 확인과 담당자 승인을 거치기 전에는 등록 대상이 아니다.

이 수치는 규칙 실행 결과이지 정답률이 아니다. 전체에 대해 사람이 정답을 작성한 데이터는 없으며 ERP 품목·거래처 키도 대조하지 않았다. 정상 형태로 분류된 후보에도 농장/거래처 또는 품종 해석 오류가 있을 수 있다.

## 파일에서 확인해 반영한 규칙

1. 첫 줄이 `차수 + 분류 + 품목 + 수량`, 다음 줄이 거래처인 형태를 지원한다. 기존 이미지 불량 파서는 첫 줄 수량을 누락하므로 별도의 불량 차감용 파서를 작성했다.
2. `차수·분류 / 거래처 / 품목별 수량 여러 줄`을 한 거래처의 여러 품목으로 추출한다.
3. 품목 줄 뒤 `/ 거래처` 표기는 거래처 후보로 추출한다.
4. `60cm` 같은 규격과 원문 품목명을 보존한다. 마스터 별칭이라고 추측해 실제 품목명으로 치환하지 않는다.
5. 단·대·송이·박스·스팀·BOX·묶음 등을 원문 그대로 보존한다. 소수 수량도 보존하며 임의 환산하지 않는다.
6. `2박스 (32단)`처럼 복수 수량이 한 줄에 있으면 별도 두 품목으로 만들지 않고 검토 대상으로 둔다.
7. 여러 차수나 차수 범위는 한 차수로 확정하지 않는다. 범위 표시 104개, 여러 차수 표시 102개가 검토 사유로 집계됐다. 사유는 중복 집계될 수 있다.
8. 농장/거래처/품종처럼 보이는 짧은 줄이 여러 개면 임의로 하나를 선택하지 않는다. 복수 후보 검토 사유는 277개다.
9. 수량이 없는 글, `수량 파악중`, 추가·정정 문맥, 음수 수량은 확인을 거친다. 앞선 메시지의 차수나 거래처를 다음 글에 자동 상속하지 않는다.
10. 사진·동영상만 있는 글과 삭제 표시는 자동 입력 후보에서 제외한다. `->`로 시작하는 품질 설명 속 수량을 별도 차감 품목으로 만들지 않는다.

사용자가 제시한 `SP믹스 15단` 실제 메시지는 차수 37-1, 분류 카네이션, 품목 SP믹스, 수량 15, 단위 단, 거래처 미카엘로 추출되는 것을 확인했다. 이것은 문자열 추출 검증이며 ERP 매칭 성공이 아니다.

## 산출물

- 코드: `core/defect_deduction_parser.py` — 승인이나 외부 쓰기를 하지 않는 순수 추출기.
- 재실행 도구: `scripts/learn_defect_corpus.py` — 입력 파일을 전체 분석하고 로컬 결과 생성.
- 테스트: `tests/test_defect_deduction_parser.py` — 원문 구조를 반영하되 거래처를 익명화한 21개 회귀 사례.
- 로컬 전체 결과: `data/defect_learning/20260914/extractions.jsonl`.
- 로컬 검토 대상: `data/defect_learning/20260914/needs_review.json`.
- 로컬 어휘 후보: `data/defect_learning/20260914/unverified_vocabulary.json`. 품목·거래처 문자열의 출현 빈도이며 확정 마스터/별칭 사전이 아니다.
- 로컬 집계·원본 해시: `data/defect_learning/20260914/summary.json`.

원문과 추출된 실제 업무 내용은 Git 제외 경로에만 저장했다. 저장소에는 코드, 익명화 테스트, 이 집계 문서만 추가한다. 기존 실행 매크로에 새 추출기를 연결하거나 재시작하지 않았다.

검증 결과: 새 추출기 21개 사례 및 기존 기능 포함 전체 **282개 테스트 통과**. 날짜/거래처 누락, 단위 보존, 복수 품목, 포장 병기, 차수 범위, 삭제, 작성자 별칭, 규격 보존을 포함한다.

## 이후 학습과 연결

실마스터 대조와 담당자의 `맞아 / 틀려 → 품목명 정정 → 재매칭 → 재승인` 결과가 쌓이면, 원문 문자열·정정 품목·실제 ERP 키·적용 범위를 함께 저장해 검증된 사례로 축적한다. 한 담당자의 정정을 모든 농장·규격에 무조건 적용하지 않는다. 현재 어휘 후보는 이 단계의 정답 자료가 아니며 단독으로 자동 입력에 사용하지 않는다.
