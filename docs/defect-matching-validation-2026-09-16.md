# 불량 매칭 학습·검증 결과

## 결론과 범위

2026-09-16 고정한 v4 매칭 규칙은 학습에 사용하지 않은 32차 카톡과 33차 전산 불량차감 중 연결 가능한 27개 품목에서 24개 일치(88.89%), 보류 3개, 잘못 선택 0개였다. 동일 표본에서 변경 전 HEAD(80a635e)는 5/27(18.52%)였다. **대조 가능한 표본에서 목표 80%를 넘었으며 전체 신규 메시지 정확도 80%를 보장하는 결과는 아니다.**

원문 38개 메시지에서 추출된 품목은 37개, 전산과 일대일 연결한 품목은 27개(72.97%)다. 나머지 10개는 품목/거래처 연결 불명확, 집계·수량 변경, 전산 대응 없음 등으로 정답을 확정하지 않았다. 이를 실패로 보는 보수적 확인 비율은 24/37(64.86%)다. 소표본이며 같은 기간·담당자·반복 품종의 자료라 다른 시기 일반화는 아직 검증하지 않았다. 오매칭 0건도 향후 무오류를 뜻하지 않는다.

## 학습과 평가 분리

신경망 재학습이 아니라 실제 원문과 마스터를 근거로 품종/거래처 별칭과 보수적 매칭 규칙을 보완했다.

- 36·35차 개발 후 34차 독립 평가: 24/36(66.67%). 미달 자료를 개발 자료로 전환했다.
- 34차까지 개발한 v3의 33차 독립 평가: 31/41(75.61%), 보류9/오선택1. 중국 원산지 누락을 확인한 뒤 개발 자료로 전환했다.
- 33차까지 개발한 v4를 고정한 후, 처음 본 32차로 최종 평가: 24/27(88.89%). **32차 실패 사례는 v4 수정에 사용하지 않았다.**

전산에는 카톡 차수보다 다음 차수에 반영한 기록이 많아 원문 차수와 차감 차수를 분리했다. 원문/전산 거래처·품목·수량을 수동 대조해 정답 연결을 먼저 만들고 예측을 확인했다. 개발자 자체 주석이므로 독립된 사람의 재검수는 미실시다. 동일 고객/품목이라도 수량이 변경·합산된 행은 정확한 일대일 정답에서 제외했다. 두 메시지의 같은 전산 행 중복 사용도 금지했다.

최종 평가는 거래처키(CustKey), 품목키(ProdKey), 절댓값 수량, 정규화한 단위가 모두 일치해야 정답이다. 대/스팀/스팀(대)/송이는 검증상 같은 줄기 단위로 보았으며 박스/단 환산은 하지 않았다. 규격은 품목키에 포함된다. 가격·원산지 명시가 없는 실제 선택의 적절성·등록 완료·비주문 대화 배제율은 이 지표가 측정하지 않는다.

## 변경한 동작

- 숫자가 포함된 품종명으로 숫자 상품코드를 부분 검색하던 오류 차단. 정확한 숫자키 입력만 코드 선택 가능.
- 농장 이름 일부가 거래처명에 들어 있다는 이유로 거래처를 선택하지 않음. 확인된 별칭이나 정확한 이름만 사용.
- 복수 실제 거래처 또는 중복 마스터 항목은 보류.
- 품종 한글 별칭, 수국 색상, 거래처 약칭 보강.
- 중국·네덜란드 등 명시 원산지별 후보 제한 및 중국 만달라와 콜롬비아 만달라 분리.
- 명시 규격과 기본50cm, 담당자별 승인, 수정 후 재승인, 결과 불명 재전송 금지 유지.

최종 보류는 거래처 약칭 한 건, 품목 별칭/중복 후보 두 건이다. 자동 처리율을 올리기 위해 애매한 후보를 강제 선택하지 않았다.

## 운영과 안전 검증

격리 복제본에서 pytest **339개 통과**. 운영 data에서 pytest를 실행하지 않았다. 실제 카톡 발송이나 웹 등록을 평가에 사용하지 않았다. 역사 원문을 운영 승인 큐에 넣지 않았다.

최종 표본의 기존 `ready()` 조건을 만족한 품목은22/27(81.48%)다. 매칭된 두 건의 원문 단위 `송이`는 현재 운영 저장 경로의 허용 단위와 달라 승인 완료 후 등록 성공률로 해석하면 안 된다. 이번 작업은 매칭 개선이며 실제 웹 저장 완료 검증은 별도다. 기존 일시정지 유지, 수입방 주문등록 보류 유지.
